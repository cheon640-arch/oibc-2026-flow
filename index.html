Steps

단계별로 하는 일
01EDA데이터 생김새 훑어보기+

본격적으로 만들기 전에 데이터가 어떻게 생겼는지 눈으로 확인하는 단계입니다.

  • 파일마다 기간이 언제부터 언제까지인지, 빈칸은 얼마나 있는지
  • 발전소마다 얼마나 크고, 평소에 얼마나 발전하는지
  • 예보 A와 B 중 어느 쪽이 실제 날씨와 더 잘 맞는지
  • 전기값(SMP)이 비싼 시간대가 언제인지

결과물

eda.ipynb
데이터 요약표
02전처리빈칸 채우고 이상한 값 정리+

모델이 헷갈리지 않게 데이터를 깨끗하게 만드는 단계입니다.

  • 예보에 빠진 칸 채우기 (빠진 시간도 채점하니까 지우면 안 됨)
  • 발전소 크기보다 큰 값, 며칠씩 0만 나오는 고장 구간 정리
  • 시간 맞추기: 01:00 값은 00시~01시 동안의 값
  • 전날 17시 이후에 생긴 정보는 절대 쓰지 않기

결과물

preprocess.py
정리된 데이터 파일
03피처 엔지니어링모델에 줄 힌트 만들기+

원래 데이터에 없는 유용한 정보를 계산해서 붙여주는 단계입니다.

  • 그 시간에 해가 얼마나 높이 떠 있는지
  • 구름 한 점 없을 때 받을 수 있는 최대 햇빛 양
  • 발전량을 발전소 크기로 나눠서 큰 곳과 작은 곳을 같은 기준으로 비교
  • 예보 A·B, 오전 10시·오후 5시 예보를 모두 활용

결과물

features.py
04검증 설계핵심우리끼리 점수 매기는 도구 만들기+

제출은 20번밖에 못 합니다. 그래서 대회 채점 방식을 똑같이 따라 하는 로컬 채점기를 만들어, 제출하지 않고도 점수를 확인합니다.

  • 대회 점수 계산식을 그대로 코드로 옮기기
  • 지난 기간 중 마지막 몇 주를 떼어 두고 시험지처럼 사용
  • 처음 1~2번 제출해서 우리 점수와 리더보드 점수가 같이 움직이는지 확인

결과물

scorer.py
입력: 묶음 배정, 예측, 실제값
출력: 점수 S
05모델링발전소별 발전량 맞히기+

날씨 예보를 보고 내일 시간별 발전량을 예측하는 모델을 만듭니다.

  • 먼저 간단한 기준 모델: 발전소 크기 × 예보 햇빛 양
  • 그다음 LightGBM 같은 머신러닝 모델
  • 전기값이 비싼 시간대를 더 정확히 맞히도록 학습
  • 발전소별로 예측해서 더하기 vs 묶음 전체를 바로 예측하기 비교

결과물

train.py
예측 결과 (07단계에서 사용)
06앙상블여러 모델의 답을 섞기+

모델 하나보다 여러 모델의 답을 적당히 섞는 쪽이 보통 더 잘 맞습니다.

  • 예보 A로 만든 모델, 예보 B로 만든 모델을 섞기
  • 종류가 다른 모델끼리 섞기
  • 섞는 비율은 로컬 채점기 점수가 제일 좋은 쪽으로

결과물

ensemble.py
07조합 최적화핵심253곳을 A·B 두 묶음으로 나누기+

벌점은 묶음 전체의 틀린 양으로 매깁니다. 한 곳이 많이 틀리고 다른 곳이 반대로 틀리면 같은 묶음 안에서 서로 지워집니다.

  • 지난 기간 예측이 발전소마다 언제, 어느 방향으로 틀렸는지 확인
  • 같이 틀리는 발전소(가까운 곳, 같은 날씨)는 서로 다른 묶음에 나눠 담기
  • 나누는 방법이 너무 많아서 다 해볼 수 없으니, 조금씩 바꿔 보며 점수가 오르는 쪽을 찾기
  • 다른 기간으로도 점수가 좋은지 다시 확인

08후처리말 안 되는 값 바로잡기+

모델이 낸 답 중 현실적으로 불가능한 값을 고칩니다.

  • 밤에는 발전량 0
  • 발전소 크기보다 큰 값은 최대치로 자르기
  • 묶음 전체가 계속 많게(또는 적게) 예측되면 그만큼 보정
